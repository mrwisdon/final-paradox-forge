# B8 僵尸超级矩阵：DeepSeek 后续开发目标

更新日期：2026-08-02

本文是后续开发的目标、边界和验收标准，不是“已经完成”的声明。当前仓库只完成了僵尸超级矩阵的第一版复原模型；完整 Boss 战仍需按原版命令链逐项迁移。

## 1. 最终目标

在 Forge 1.20.1 / Java 17 的 `final-paradox-forge` 中，严格复原 Final Paradox v1.1.15 的 B8 Boss 战“僵尸超级矩阵”，并与已经复原的大地漫游器协同工作。

完成后的战斗必须覆盖：

- 正式进场、倒计时、玩家与载具分配；
- 固定竞技场内的僵尸超级矩阵；
- 250 点矩阵生命、Bossbar、无敌和易伤状态；
- 200、150、100、50 点生命阈值对应的五阶段流程；
- 原版机关、增援波次、玩家载具受伤、子弹命中和拦截；
- 对话、标题、音效、粒子、音乐；
- 玩家死亡、全灭失败、胜利、奖励和完整清理；
- 单人和多人状态一致，服务器重载后不会留下幽灵战斗或重复实体。

“能构建”不等于“复原完成”。只有代码、行为、视觉、声音和文本都经过游戏内对照，才能宣称对应部分完成。

## 3. 当前已经完成的部分

### 模型实体

- `ZombieSupermatrixEntity`：同步紧凑/易伤状态、旋转时钟、待机粒子和开合反馈。
- `ZombieSupermatrixRenderer`：用一个复合渲染器重建原版 14 个金块头盔部件、1 个海晶灯头盔部件、中心灯笼和名字。
- `ModEntities` 和 `ClientModEvents`：实体及客户端渲染器已经注册。

### 明确尚未完成

当前实体没有正式生命系统、Bossbar、攻击判定、阶段控制器、怪物波次、胜败逻辑、奖励、竞技场所有权或音乐。它不可碰撞、不可选取且始终无敌；这些是第一阶段模型的刻意边界，不是最终战斗设计。

中心灯笼目前只由渲染器显示，不会修改世界方块。正式遭遇控制器必须决定是否在源位置放置真实灯笼，并负责退出、失败和重载后的清理。

## 4. 强制开发原则

1. 开始任何修改前，完整阅读工作区 `AGENTS.md` 和 `recreate-minecraft-map-items` 技能说明。
2. 新问题先做只读诊断，列出证据、根因、影响文件和拟议修正，得到用户确认后再改。
3. 每个子系统先追踪完整 mcfunction 调用链，并把常量、计时、选择器、随机分支和清理路径记录到 `docs/reconstruction/`。
4. 战斗状态由服务器唯一持有；客户端只负责渲染、插值、声音和轻量表现。
5. 不要用大量联网盔甲架照搬原版。继续使用复合渲染器或专用轻量实体，但输出必须与原版一致。
6. 不要静默近似。确实无法一比一迁移时，先记录差异并向用户说明。
7. 每次实现后必须检查实际 diff、执行构建、同步 JAR、校验 SHA-256，并在游戏内观察相关阶段。
8. 保留当前大地漫游器的稳定性：腿、炮塔、驾驶位、上下车、持续射击和粒子/音效不能回归。

## 5. 必须完成的里程碑

### M0：确认当前模型基线

在继续写战斗逻辑前，先完成紧凑和易伤模型的游戏内对照：

- 正面、侧面、顶部各截图一组；
- 静止观察至少 10 秒，确认没有部件抖动或接缝跳变；
- 确认三组圆环的旋转方向和每 tick 3 度；
- 确认开合插值、名字高度、中心海晶灯、灯笼和光照；
- 记录与原版截图的任何差异，不能仅凭“整体看起来可以”关闭此项。

### M1：正式遭遇控制器和持久化

建立 B8 专用的服务端状态机，至少包含：

```text
IDLE -> COUNTDOWN -> PHASE_1 -> PHASE_2 -> PHASE_3 -> PHASE_4 -> PHASE_5
     -> VICTORY / DEFEAT -> CLEANUP -> IDLE
```

控制器必须持久化或可可靠恢复：竞技场锚点、当前阶段、当前轮次、矩阵 UUID、250 点生命、无敌/易伤状态、所有计时器、参加者、载具归属和待清理实体。

正式源坐标为：

- 玩家出生点：`-3817 79 1413`
- 矩阵核心：`-3828 85 1412`
- 竞技场边界中心：`-3828 78 1412`
- 非旁观玩家离中心超过 26 格时传送回 `-3815 79 1412`。

需要防止重复启动、重复矩阵、重复调度和重载后双重 tick。测试命令可以保留，但正式遭遇只能由一个控制器拥有。

### M2：玩家、大地漫游器和战斗入口

迁移 `ini_monturas/**` 与已有 `TerrastalkerRoverEntity` 的协作：

- 根据活跃玩家生成并唯一分配大地漫游器；
- 多人时正确处理观战者和驾驶员归属；
- 所有非旁观玩家完成上车后，才开始原版 3、2、1、开始的四秒倒计时；
- Boss 战期间使用遭遇模式：禁止随意下车，并遵守原版死亡/载具损毁流程；
- 未启动 Boss 战时仍保留双击 Shift 下车；
- 载具伤害必须作用于正确驾驶员的载具，不能串号或全员错误扣血；
- 对测试过的驾驶高度、炮塔旋转、前进方向锁定、连续射击特效和音效做回归验证。

### M3：矩阵生命、无敌/易伤和子弹判定

严格迁移 `matriz/**`、`setvida`、`check_vida`：

- 总生命和初始生命均为 250；
- Bossbar 名字使用原翻译键，百分比由矩阵生命计算；
- 易伤时，距离命中中心约 1.5 格的大地漫游器子弹每发扣 1 点；
- 无敌时，中心约 3 格范围内的漫游器子弹被拦截，只播放原版格挡反馈，不扣生命；
- 命中必须从子弹当前服务端位置计算，不能重现“按住 Shift 后开火点停在第一次位置”的旧问题；
- 同一发子弹最多命中一次，并由服务器清理；
- 生命恰好达到 200、150、100、50 时分别进入阶段 2、3、4、5；
- 生命降至 0 时触发矩阵爆炸和胜利链，不允许继续接受命中；
- 阶段切换时矩阵关闭并无敌；清除对应破盾机关后重新打开并易伤。

### M4：机关与攻击系统

每种机关都要独立建立证据文档、实现、测试命令和清理路径。

#### H1：直线预警与推进爆炸

来源：`h1/**`。

- 从竞技场中心朝玩家或随机方向生成路径；
- 前 100 tick 按原版几何显示 end-rod 预警；
- 101 tick 后每 tick 沿局部前方推进 2 格，到 114 tick 清除；
- 爆炸包含原版圆环、中心连线、声音和方块碎屑；
- 4 格内每台载具每轮最多受到一次 5 点伤害。

#### H2：坠落金块模块与破盾窗口

来源：`h2/**`。

- 从中心上方的原版径向候选点选择模块位置，保留原版随机数量与玩家数量修正；
- 金块模块发光并以每 tick `0.036` 格下落、每 tick 旋转 3 度；
- 漫游器子弹在约 1.5 格范围击碎模块，播放原版粒子和音效；
- 模块落到底部触发原版爆炸和 5 点载具伤害；
- 所有模块消失后等待 2 秒，再把矩阵切换为易伤状态；
- 重复调度、重载或阶段切换不能提前打开矩阵。

#### H3：增援单位

来源：`h3/**` 和依赖的 affix/载具函数。

需要逐个复原并保留原版生成数量、出生点筛选、生命、装备、名称、移动速度、攻击和死亡行为：

- zombie robot；
- sniper skeleton 及其 conduit 子弹；
- iron golem；
- TNT skeleton；
- acechador / 大地漫游器敌对单位。

Sniper 子弹必须朝最近玩家载具发射、每 tick 前进 `0.4` 格，在命中地形、载具或玩家子弹时爆炸；载具命中伤害为 2。增援计数必须由当前存活的 B8 add 计算，不能因为卸载、错误标签或死亡动画卡住轮次。

#### H4：旋转区域爆炸

来源：`h4/**`。

- 原版生成三条不同半径的旋转扫描源，前 20 tick 建立预警区域；
- 预警实体每 tick 旋转 7 度，100 tick 后爆炸；
- 爆炸半径、粒子、中心连线和音效按原命令迁移；
- 5.5 格内载具受到 5 点伤害；
- `ini`、`ini2`、`ini3` 的生成次数和 0.5 秒/4.5 秒追加时序必须分别保留。

### M5：五阶段和轮次编排

阶段和波次的权威来源是 `fase/**`，不能自行重新设计难度曲线。

- 阶段 1：生成载具；所有驾驶员就位后四秒倒计时；首次执行 H2，随后开放矩阵易伤。
- 阶段 2（生命 200）：矩阵无敌；三轮 zombie robot 增援，清理条件按 `b8_add_count`；第四轮按源文件时间轴组合 H1、H2。
- 阶段 3（生命 150）：矩阵无敌；sniper、zombie robot 混合轮次；第四轮按源时间轴组合 H4、H1、H2。
- 阶段 4（生命 100）：矩阵无敌；iron golem、TNT skeleton、zombie robot 轮次；第五轮按源时间轴组合 H4、H1、H2。
- 阶段 5（生命 50）：矩阵无敌；golem、robot、sniper、acechador 轮次；第七轮按源时间轴组合 H4、H1、H2。

每一个 `schedule ... Ns append` 都必须换算为准确 tick，并放进同一个服务端时间轴。不能直接依赖全局静态变量，也不能因为玩家退出或服务器重载重复派发波次。

### M6：载具伤害、玩家死亡和失败

迁移 `danar_montura*`、`morir`、`derrota`、`respawn`：

- 每次机关伤害只扣目标载具对应的耐久/能量，并显示原版损伤消息；
- 载具摧毁后的驾驶员处理与原版一致；
- 玩家死亡进入旁观模式并传送到 `-3828 91 1412`；
- 所有参战玩家均为旁观者时触发失败；
- 失败标题、声音和 5 秒后 respawn 流程完整；
- respawn 后清除凋零等遗留效果、恢复正确游戏模式，并回到可重新挑战状态。

### M7：胜利、奖励和清理

迁移 `explosion`、`victoria`、`reset`、`omitir`：

- 0 生命时播放原版金块碎片、云、闪电、声音和中心爆炸；
- 停止 Boss 音乐并进入胜利音乐/庆祝流程；
- 正确恢复旁观玩家、出生点和游戏模式；
- 生成原版 `megamatriz_perneras` 奖励或其 Forge 等价实现；
- 清除矩阵、增援、机关、子弹、临时方块、Bossbar、定时任务和 forceload；
- 胜利、失败、管理员 reset、跳过、服务器关闭/重载五条路径都必须幂等；
- 清理后世界中不能残留不可见实体或继续播放的循环音乐。

### M8：文本、声音和音乐

- 从指定 VM 汉化包逐键复制 B8 中文，不要自行润色；
- 英文文本使用原资源包对应键；
- 迁移阶段标题、警告、副标题、载具伤害消息、胜败消息和全部 B8 对话；
- 对话显示时序以实际函数链为准；
- 迁移 `bossfight/musica/megamatriz/**` 的音乐片段、循环、停止和胜利切换；
- 声音资源与原版来源许可不明确时，不要提交归档或资源，先记录阻塞并请用户确认。

## 7. 测试和验收矩阵

每个里程碑至少要通过以下层级：

### 静态检查

- Java 17 编译通过；
- 所有 JSON 可解析；
- 每个自定义客户端追踪实体都有渲染器；
- `git diff` 中无原版归档、缓存、构建目录或无关文件。

### 自动/命令烟雾测试

- 能单独生成、切换、移除矩阵；
- 能单独触发 H1、H2、H3、H4；

### 游戏内行为测试

- 单人完整通关一次；
- 双人完整通关一次，验证载具归属和伤害不串号；

- 胜利后能再次进入竞技场且无旧实体、Bossbar、音乐和调度残留。
